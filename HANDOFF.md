# Hand-off: ZX Spectrum → локальна розробка

**Проєкт:** освітній розділ ZX Spectrum для Software and Computer Museum
(`spectrum.sncmuseum.org`)
**Що зроблено в цій сесії:** реалізовано сторінку **Каталог моделей** (`/models/`)
з усіма спільними компонентами, як робочий Astro-проєкт.
**Кому передається:** розробнику для продовження в локальному середовищі
(редактор + Node.js, за бажанням — Claude Code CLI).
**Дата:** 2026-07-15

---

## 0. TL;DR — з чого почати локально

```bash
# 1. Розпакувати архів проєкту (spectrum-sncmuseum.zip)
# 2. Переконатися, що встановлено Node.js ≥ 22.12  (nvm use — читає .nvmrc)
npm install
npm run dev
# 3. Відкрити http://localhost:4321/models/  (UA)  та  /en/models/  (EN)
```

Далі читати цей документ від розділу 3 (структура) і 7 (наступні кроки).

## 1. Контекст і джерела істини

Порядок пріоритету документів (за розбіжностей — вищий переважає):

## 2. Стек і ключові рішення

| Пункт | Рішення | Примітка |
|---|---|---|
| Фреймворк | **Astro** (у сесії 5.18.2) | ⚠️ ТЗ вказує **Astro 7** (Rolldown/Sätteri) — його ще немає в npm. Код написано під архітектуру 7 (Content Collections, `astro/loaders`, i18n) — оновлення буде drop-in, коли 7 вийде. Див. розділ 6. |
| Node.js | ≥ 22.12 | зафіксовано в `.nvmrc` |
| Мова коду | TypeScript (strict) | `npm run check` = 0 помилок |
| Контент | Content Collections + Zod | `src/content.config.ts` валідує `src/data/models.json` на етапі збірки |
| i18n | вбудований Astro i18n | `uk` — без префікса, `en` — `/en/`; `prefixDefaultLocale:false` |
| Інтерактив | один клієнтський «острів» (vanilla `<script>`) | фільтри + компаратор; **без** JS-фреймворку — сторінка майже без JS |
| Зображення | `astro:assets` | авто-оптимізація у WebP (у білді — 4 фото × 3 розміри) |
| Стилі | scoped CSS у компонентах + токени в `theme.css` | без CSS-фреймворку |

**Свідомі спрощення відносно ТЗ (потребують уваги — розділ 7):**
- Каталог містить **8 моделей** з дизайну, а не повний MVP-перелік на 20 (ТЗ §8.3).
  Схема вже це підтримує — треба лише дописати записи.
- `inventory_id` ще немає в схемі. ТЗ §14 вимагає: поле `optional`, але за
  `in_museum: true` CI має вимагати його наявність. Зараз 3 моделі з
  `inMuseum: true` — інвентарних номерів на них у репозиторії немає, їх дає музей.

## 4. Дизайн-система (швидкий довідник для нових сторінок)

Усі значення — у `src/styles/theme.css` як CSS-змінні. Використовувати їх, не хардкодити.

**Колір:** `--bg:#000` · `--text:#D7D7D7` · `--text-dim:#A8A8A8`.
ZX BRIGHT: `--zx-red/#FF0000`, `--zx-magenta/#FF00FF`, `--zx-cyan/#00FFFF`,
`--zx-yellow/#FFFF00`, `--zx-white/#FFFFFF` (можна текстом);
`--zx-blue/#0000FF`, `--zx-green/#00FF00` (**лише заливка/рамка**).
Музей: `--museum-navy/#152A52`, `--museum-gold/#FFD700` (службові зони).

**Типографіка:** `--font-pixel` (Retroville, заголовки/UI ≥16px, UPPERCASE) ·
`--font-body` (Golos Text, ≥18px, LH 1.6) · `--font-mono` (IBM Plex Mono, роки/метадані).

**Форма:** кути 0 (ретро); елевація рамками, не тінями; сітка контенту ~1180px;
райдужна смуга — акцент/роздільник (не шпалери). Рух 160–240ms ease-out;
поважати `prefers-reduced-motion`. Фокус — видима 2px рамка (blue).

**CRT-режим:** клас `html.crt`, стан у `localStorage['zx-crt']`, накладка
`.crt-overlay` у `BaseLayout`. За замовчуванням вимкнено.

## 5. Модель даних

`src/data/models.json` — масив, кожен запис валідовано схемою `src/content.config.ts`:

```jsonc
{
  "id": "zx-spectrum-48k",          // = slug, формує /models/{id}/
  "title": { "uk": "...", "en": "..." },
  "manufacturer": "Sinclair",
  "country": "GB",                   // enum GB|PT|US|PL → локалізована назва в UI
  "year": "1982",
  "ram": "48 KB",
  "ramKb": 48,                        // null = невідомо
  "desc": { "uk": "...", "en": "..." },
  // [] → картка «Шукаємо фотографію». Перше зображення — обкладинка картки.
  "images": [
    {
      "src": "zx-48k.jpg",           // файл у src/assets/models/
      "alt": { "uk": "...", "en": "..." },
      "license": "CC-BY-SA-2.5",     // enum з src/lib/licenses.ts (ТЗ §14)
      "author": "Bill Bertram",
      "source_url": "https://commons.wikimedia.org/wiki/File:ZXSpectrum48k.jpg",
      "accessed": "2026-07-17"
    }
  ],
  "inMuseum": true,
  "confidence": "high"               // high|medium|low; low → бейдж «⚠ уточнення»
}
```

**Ліцензійні поля — тверде правило (ТЗ §7.2).** Усі чотири (`license`, `author`,
`source_url`, `accessed`) обов'язкові. Дві лінії захисту:

1. **Zod** (`src/content.config.ts`) — валить `astro build`, якщо поля бракує.
2. **`npm run check:licenses`** (`scripts/check-licenses.ts`) — ловить те, чого схема
   не бачить: файл відсутній на диску, файл-сирота без задокументованої ліцензії,
   джерело поза ієрархією ТЗ §7.1, `accessed` із майбутнього або неіснуюча дата.
   Дає читабельний звіт замість стектрейсу. У CI йде **перед** збіркою.

`commercial_use` не пишеться руками — виводиться з `license` (ТЗ §14),
див. `deriveCommercialUse()`.

**Фільтри** виводяться з даних автоматично (`buildFilterGroups`): рік · виробник ·
країна · обсяг ОЗП · наявність. Додаси нову модель — чипси оновляться самі.

## 6. Astro 5 → 7: що зміниться при апгрейді

Коли вийде Astro 7 (ТЗ §3), оновлення має бути мінімальним:
- `package.json`: `astro@^7`; Node лишається ≥ 22.12.
- Компілятор Rust суворіший до розмітки — поточна розмітка валідна (0 помилок check),
  але прогнати `npm run build` і виправити, якщо щось спливе.
- Content Collections / `file()`-loader / i18n API у коді вже в «новому» стилі —
  міграції не очікується.
- Перевірити ремарк/рехайп-плагіни (у нас їх немає → нічого робити).

Поки 7 немає — лишатися на 5.x. Нічого «майбутнього» в коді не використано.

## 8. Відомі особливості / підводні камені

- **Google Fonts у пісочниці Claude:** у веб-сесії запити до fonts.googleapis.com
  блокуються сертифікатом — на скриншотах основний текст був системним шрифтом.
  **Локально й у проді шрифти вантажаться нормально.** (Retroville self-hosted —
  працює скрізь.) За бажанням — self-host і Golos Text/IBM Plex Mono для офлайну й швидкості.
- **Гарячі посилання на Wikimedia** були прибрані ще в дизайн-фазі; усі фото —
  локальні у `src/assets/`. Не повертати хотлінки (етикет + надійність).
- **«Мертві» пункти меню:** Історія/Клони/Софт/Периферія/Експонати/Контакти
  ведуть на ще не створені адреси (404). Це очікувано до збірки тих сторінок.
- **Горизонтальний скрол на 320px** (ТЗ §10 вимагає 320–1920). Дві причини, обидві
  **не** в картці моделі: `Header.astro` (`.hd-tools`/`.menu-toggle` виходять за межі —
  через це їдуть **усі** сторінки) і `CatalogView.astro` (`.results{min-width:280px}`
  при доступних 264px + немає одноколонкового брейкпоінта). Винесено окремою задачею.
- **Фото `zx-plus3.jpg` темне й дуже широке** (4000×1828, ~2.2:1) — це знімок
  експоната на стіні, не студійний кадр. У hero-боксі 4:3 з `object-fit:contain`
  воно летербоксується у вузьку смугу й на чорному тлі майже зникає. Верстка
  коректна — питання до самого фото (ТЗ R3). Варіанти: знайти інше фото з чистою
  ліцензією або зняти власне.
- **`project/` не збирається** Astro (поза `src/`), лишається як референс. У
  `tsconfig` виключено.

## 9. Перевірка якості (як переконатися, що нічого не зламалось)

```bash
npm run check    # типи: очікувано 0 errors
npm run build    # має завершитись "Complete!", 4 сторінки, оптимізовані webp
```

У цій сесії функціональність підтверджено e2e у браузері (25/25):
рендер 8 карток; фільтр Amstrad → «3 з 8 моделей»; комбінація Amstrad+Португалія →
стан «нічого не знайдено» + компаратор ховається; «Скинути» з обох кнопок; Португалія
→ лише Timex; фільтр «В музеї» → 3; зняття моделі з компаратора оновлює лічильник і

зберігається в localStorage; EN повністю локалізовано.

Для повторної e2e-перевірки локально — Playwright проти `npm run preview`

## 12. Локальне середовище

**Node.js на робочій машині не встановлено** (станом на 2026-07-15: немає ні
`node`, ні nvm, ні Homebrew). Поки його немає — `npm install`, `npm run dev`,
`npm run check` і `npm run build` не запускаються, тобто **жодна зміна коду не
перевіряється локально**. Це перше, що треба зняти.

Потрібно: **Node.js ≥ 22.12** (зафіксовано в `.nvmrc`; вимога ТЗ §3).

Два шляхи:

1. **Інсталятор** — [nodejs.org](https://nodejs.org/) → LTS для macOS (`.pkg`).
   Найпростіше, якщо потрібна одна версія Node.
2. **nvm** — якщо колись знадобляться різні версії під різні проєкти:
   ```bash
   curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
   # перезапустити термінал, далі в теці проєкту:
   nvm install    # прочитає .nvmrc
   nvm use
   ```

Після встановлення — перевірка, що все живе:

```bash
node -v          # має бути ≥ v22.12
npm install
npm run check    # очікувано: 0 помилок
npm run build    # очікувано: "Complete!"
npm run dev      # → http://localhost:4321/models/
```
